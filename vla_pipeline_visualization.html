🔍 为什么正好是 1536 维？
1536 是整个 Action Head 的统一特征空间维度（input_embedding_dim）， 后续所有模块（state编码器、动作编码器、DiT模型）都在这个维度上操作。

3 个数据组件最终会拼接成一条序列送入 DiT，因此维度必须一致：
VL 特征（此步） backbone 输出 2048D → LayerNorm + Self-Attention → 1536D 在此块完成
state 特征 26D → padding(64D) → MLP(64→1024→1536) 第7块完成
action 特征 [B,64,128] → 动作编码器 → 1536D 第8块完成
// 三者维度统一为 1536 后拼接： sa_embs = torch.cat([state_features, action_features], dim=1) // [B, 65, 1536]

🎬 现实类比
这步是整个训练的关键！想象一下：
你先用 随机乱画的一条线 代替真正的拿杯子轨迹， 然后慢慢 把乱画修正成正确的轨迹。
模型学的就是"怎么从乱画修正好"这个能力。
Flow Matching 一种训练方法：给标准动作加不同程度的噪声（弄模糊），让模型学习"怎么还原清晰动作"。就像教学生从涂鸦逐步画成素描。

三步核心公式：
// ① 生成随机噪声 + 随机时间步
noise ~ N(0, 1)
t ~ Beta(1.5, 1.0) // [0, noise_s] 范围, 0=全乱→1=完全清晰

// ② 混合：把噪声和真值按 t 比例混合
noisy = (1−t)×noise + t×actions

// ③ 目标：从噪声走向真值的"修正方向"
velocity_target = actions − noise // ★ 真值速度(模型要学的速度场方向)
pred_velocity = DiT(noisy, backbone, t, state) // ⭐ DiT 就是速度场网络，输入噪声动作+条件，输出指向真值的速度（关于DiT的定义详见第10块）

// ── 推理时：从纯噪声开始，逐步去噪 ──
action = noise // 从纯噪声开始
action += dt × DiT(action, backbone, t, state) // 逐步修正（关于DiT的定义详见第10块）

// ── 关键配置 ──
num_timestep_buckets=1000（时间步离散化桶数）
num_inference_timesteps=4（推理去噪步数）
🔍 Beta(1.5, 1.0) 和 noise_s 是什么？
Beta(α=1.5, β=1.0) — 一种定义在 [0,1] 上的连续概率分布。
α > β ⇒ 概率密度偏向 1.0，即采样值 s 更多集中在 1 附近。
经 t = (noise_s − s) / noise_s 变换后：t 更多落在接近 0 的位置（嘈杂区域）。
效果：模型花更多时间训练"从极嘈杂的噪声中恢复"——对困难样本过采样，提升鲁棒性。
action_head_base:101 Beta(noise_beta_alpha=1.5, noise_beta_beta=1.0)

noise_s = 0.999 — 时间步缩放系数，控制 t 的取值范围。
归一化公式：t = (noise_s − s) / noise_s，将 t 映射到近似 [0, 1] 区间：
• t=0 ⇒ noisy = noise（纯噪声）
• t=1 ⇒ noisy = actions（完全清晰）
• noise_s < 1 时 t 可略<0（当 s > noise_s 时），覆盖"略超纯噪声"的极端场景
config noise_s: float = 0.999 action_head:38
配合 num_timestep_buckets=1000：t_discretized = (t × 1000).long() 将连续 t 量化到离散桶。

noisy = 0.7×noise + 0.3×actions
第0帧: 0.7×[-0.80,1.20,0.50] + 0.3×[0.10,0.20,0.30] = [-0.53, 0.90, 0.44]
第1帧: 0.7×[ 0.30,-0.70,1.10] + 0.3×[0.40,0.50,0.60] = [ 0.33,-0.34, 0.95]

// ── velocity（模型要学的目标）─ 与 t 无关！──
velocity = actions − noise
第0帧: [0.10,0.20,0.30] − [-0.80,1.20,0.50] = [ 0.90, -1.00, -0.20]
第1帧: [0.40,0.50,0.60] − [ 0.30,-0.70,1.10] = [ 0.10, 1.20, -0.50]
🧠 核心洞察：velocity 与 t 无关
不管这条训练样本这次抽到 t=0.3（七分噪声）还是 t=0.7（三分噪声），
要学的 velocity 始终是 [0.90, -1.00, -0.20]，不随 t 变化！

因为 velocity = actions − noise 只由终点（真值）和起点（当前噪声）决定，
与走在路径上的哪个位置（t）无关。

换句话说：模型在 整条路径上的每一个中间位置 看到的都是一样的前进方向。
训练时随机抽 t 只是为了让模型在所有位置都见过这个方向——
t=0 时（纯噪声）知道往哪走，t=0.5 时（半路）也知道往哪走。

🔍 DiT 到底长什么样？为什么不是 MLP？
DiT（Diffusion Transformer） 是整个 Action Head 参数最多的核心网络。它不是一个简单的 MLP，而是一个 32 层的完整 Transformer（dit.py:174-288）：

输入 sa_embs [B, 65, 1536]          ← 状态+噪声动作（AltDiT 无 future_tokens，第9块）
   │
   ├─ TimestepEncoder(t)            ← 把"噪声程度t"编码成条件信号
   │
   ├─ 32 × BasicTransformerBlock    ← ★ 核心计算（不是MLP！）
   │   ├─ 奇数层: Self-Attention    ← 动作序列65步之间互相"商量"
   │   ├─ 偶数层: Cross-Attention   ← 动作序列"看"VL理解结果 [B, 822, 1536]
   │   └─ 每层受 AdaNorm(t) 调控    ← 不同噪声程度用不同处理方式
   │
   ├─ LayerNorm + 条件投影           ← 自适应归一化（shift+scale受t控制）
   └─ Linear(1536→1024)            ← 降维输出
                                      │
                                      ▼
       latent_embs [B, 65, 1024] → action_decoder → pred_velocity [B, 64, 128]
关键设计：
• 内维度 = 1536（32头 × 48维/头），正好等于 input_embedding_dim，保证输入直接匹配
• 交错注意力：奇数层只做自注意力（序列内部交互），偶数层做交叉注意力（看VL特征），action_head:60
• AdaNorm：每层的输出受时间步 t 控制——t小（嘈杂）时强调降噪，t大（清晰）时强调细节精修
• 不是MLP：MLP只有2层线性层（无序列交互、无外部参考），DiT有32层+32头注意力+VL特征交叉引用，参数量高出几个数量级

★ 算分：预测和正确答案差多少？ action_head:505-544
🎬 现实类比
你让机器人试着做一遍拿杯子，
然后 对比机器人的动作和你的示范动作：
"嗯，你 shoulder 转多了 5 度，elbow 弯少了 8 度，这里差 3 分，那里差 2 分"
MSE Loss（均方误差） Mean Squared Error，就是"预测值 - 真实值"的平方，然后平均。平方是为了让"大错误"更突出（比小错误多扣分）。
例：差1分→扣1分，差3分→扣9分（大错误更严重）
错误分 = 平方差(预测的修正, 正确的修正) × 有效掩码

最终分数 = 总分 / 有效帧数
action_mask（有效掩码） 有些时刻的关节数据可能是空的（没录到），action_mask=0 表示"这帧不算分"，action_mask=1 表示"这帧要算分"。就像一个考试时告诉你"这些题不算分，那些题算分"。

❓ 为什么 4 步就够了？不是应该像传统扩散模型那样跑 1000 步吗？
Flow Matching 和传统 DDPM（去噪扩散概率模型）走的是完全不同的路：

DDPM 逐步加噪/去噪，路径是弯曲的（类似随机游走），每一步只能走很小，需要 1000 步
Flow Matching 直接学"从噪声到真值的直线方向"，路径是直的，4 大步就能走到底

原因拆解：
• 训练时目标 velocity = actions − noise 就是"连接噪声和真值的直线方向"（action_head:305）
• 推理时用 欧拉积分：dt = 1/4 = 0.25，每次 action += 0.25 × pred_velocity
• 4 步之后 action 从纯噪声走到 ≈ 真值位置，相当于把整条直线均匀切了 4 段

💡 类比：DDPM 像盘山路绕 1000 个弯下山，Flow Matching 像坐直梯直接到一楼 —— 路径设计不同，步数自然差了两个数量级。

Loss 函数的完整数学表达 action_head:530-533
🎬 一句话
Loss = 预测的修正方向与真实的修正方向的差的平方（只算有效维度）
# Python 代码：action_head_dit.py L530-533

action_loss = F.mse_loss(pred_velocity, velocity, reduction='none')
// 每个位置的平方差，shape=[64, 64, 128]

action_loss = action_loss * action_mask
// 乘以掩码：填充的维度为0（不算分）

loss = action_loss.sum() / action_mask.sum()
// 最终损失 = 总分 ÷ 有效帧数

详细拆解：
  pred_velocity[0, 5, 0] = 0.12   velocity[0, 5, 0] = 0.08
  差 = (0.12-0.08)² = 0.0016   乘 mask=1   算分 ✔
  pred_velocity[0, 5, 30] = 0.05   mask[0, 5, 30] = 0   不算分 ✘
  （第30维是填充维度，实际G1只有26维）
维度级别的 loss 拆解：
  • 第1维（batch）：64条记录分别算loss，然后平均
  • 第2维（action_horizon）：64帧中，后部帧如果是padding（episode不够长），mask=0不算分
  • 第3维（action_dim）：128维中，只有前26维（14臂+12指）mask=1，后102个padding维mask=0

📖 小白版术语速查表
Tensor（张量）
多维数据容器。就像 Excel：1维=一行数字，2维=表格，3维=一叠表格。[64, 64, 32] = 64条 × 64帧 × 32个数字。
Backbone（骨干网络）
模型的"感知和理解"部分，包含视觉(SigLIP)和语言(Qwen3)。它的工作是：看懂画面、听懂指令、融合理解。训练时冻结不动。
Action Head（动作头）
模型的"动作执行"部分。它的工作是：根据 backbone 的理解 + 当前机器人状态，输出26维电机/手指期望值（14手臂电机+12灵巧手自由度）。训练时主要更新它。
Flow Matching
训练方法：对标准动作加噪声（弄模糊），让模型学习"从模糊恢复清晰"。推理时从纯噪声开始逐步去噪得到动作。核心公式：noisy = (1-t)×noise + t×action
DiT（扩散变压器）
核心动作推演网络。输入"行动方案"（状态+动作序列）和"理解结果"（视觉语言特征），输出修正后的动作预测。
MSE Loss（均方误差）
衡量预测好坏的标准。计算"预测值-真实值"的平方再平均。数值越小越准，训练的目标就是让这个值不断降低。
Gradient Descent（梯度下降）
学习的方法。计算"方向偏了多少"，然后往反方向调整参数。就像投篮不够高，下次投高一点。每步都调整，越来越准。
冻结（Frozen）
训练时不动这部分参数。项目里 SigLIP 和 Qwen3-1.7B（EagleVL2.5 骨干的 LLM 部分）都是冻结的，因为它们已经在大数据上学好了通用知识，不需要为倒水任务重新学"怎么看东西"。v0模式全部冻结，v0.5模式解冻LLM最后4层。
Batch（批次）
一次性喂给模型的数据条数。项目用 batch=64，即每次处理64条记录。批量处理比逐条处理效率高。
Feature / Embedding（特征 / 嵌入）
把图片、文字转成"计算机看得懂"的数字串。比如"杯子"这个图片 → [0.3, -0.5, 0.8, ...] 几百个数字。相似的图片有相似的数字串。
224×224
图片分辨率。224像素宽×224像素高，约5万个像素点。原始相机拍的是 640×640（约40万像素），数据加载时被强制降采样至 224×224。原因是 SigLIP 视觉编码器固定吃 224×224 的输入，而管道未启用 EagleVL 的动态分块机制来保留原图细节。这是精度 vs 显存/速度的取舍。
action_chunk（动作块）
一次预测未来多少步动作。本项目默认 64 步（约2秒，假设30fps）。这样 G1 机器人不是"走一步看一步"，而是规划一整段26维连续动作（手臂14维+手指12维）。
自由度 (DoF)
独立可控制的运动方向。G1 灵巧手每只手 6个自由度（5根手指弯曲 + 拇指对掌），双手共12个。加上手臂14个电机，总共 26个自由度。
灵巧手 (Dex Hand)
像人手一样能灵活抓握的机械手。G1 左右手各一只，每只6个自由度，可以完成握壶柄、扶杯子、捏开关等精细操作。比传统夹爪灵活得多。
填充 (Padding)
不同机器人的维度不同（8~26维），为了让模型能同时处理它们，把维度填充到固定值：action填充到128，state填充到128。多余的维度用 action_mask=0 告诉模型"这部分不算"。就像用标准信封装不同大小的照片，空位塞纸板固定。
v0 / v0.5 模式
项目提供两种训练配置。v0（蓝色）：LLM完全冻结，只训练Action Head，速度更快、更省显存。v0.5（绿色）：解冻LLM最后4层微调，精度更高、泛化更好。数据量大时推荐 v0.5。
AltDiT（交替 DiT）
DiT 的变体，在交叉注意力层中分离图像 token 和非图像 token。交替处理文本信息和非文本特征（state/action），每 N 块切换一次（attend_text_every_n_blocks=2）。v0.5 模式下使用。对应代码：alt_dit.py。
SelfAttentionTransformer
仅包含自注意力层的 Transformer，不带交叉注意力。用于 Action Head 中替代 DiT 的精炼/降噪步骤。来自 shared.py:87-154，基于 diffusers 的 ModelMixin。
TaskProgressLoss
可选的辅助 loss，预测任务完成进度（0~1 标量）。从 DiT 的 latent_emb 额外解码出 progress，与 action MSE loss 相加。启用条件：task_progress.enabled=True。
Pixel Shuffle（像素重排）
将通道维度的信息重排到空间维度，达到降采样效果。EagleVL3 用它将视觉 token 数量减半（use_pixel_shuffle=true, downsample_ratio=0.5）。1024 patches → 512 tokens，减少进入 LLM 的视觉序列长度。
SigLIP2
EagleVL3 使用的视觉编码器，相比 SigLIP 支持更大分辨率（原生 448×448 tile）、带窗口注意力和 RoPE 的改进架构。patch_size=14, hidden_size=1152, 27 层 Transformer。

🔧 数据处理流程（7 步）
1
归一化 StateActionProcessor.apply()
min_max / mean_std 归一化 + sin_cos 编码。将不同机器人量纲统一。
2
动作填充 max_action_dim=128 × max_action_horizon=64
padding 到固定维度 + 生成 action_mask 标记有效维度。
3
状态填充 max_state_dim=128
state 也 padding 到固定维度（实际 26→填充到 128）。
4
图像变换 albumentations
Resize → (RandomCrop/CenterCrop) → Resize。使用 ReplayCompose 保持多视角一致性（头部+左腕+右腕同一变换）。
5
语言处理 formalize_language=True
lower() + 去标点。仅做基本清洗，不支持同义词替换或语义增强。
6
VLM Prompt 构建 processing:apply_chat_template
构造 <image>...<image>instruction 格式，将图像占位符插入文本指令。
7
Collator 组装批次 TaoFlowMatchingDataCollator
padding + batch stack，输出最终 tensor 批次供模型消费。

当你采集了一个新机器人的数据，EagleVL（块 3+4）完全不用动， 但你需要写一份 Embodiment 配置来告诉 TAO 你的机器人长什么样。 下面以 Franka（单臂协作机器人） 的完整配置为例逐行拆解。 源文件：src/tao/embodiments/franka.py
1️⃣ observations — 你的机器人有哪些传感器？ 
# 告诉 TAO：你的数据文件里，每个 key 对应什么
observations = {
    # 摄像头：有几个？叫什么名字？
    'video': {
        'base_image':        'observation.images.main_realsense_rgb',    ← 主摄像头（场景视角）
        'left_wrist_image':  'observation.images.handeye_realsense_rgb',  ← 左腕摄像头
        'right_wrist_image': 'observation.images.side_realsense_rgb',   ← 右腕摄像头
    },  ← 注意：所有机器人统一用 3 相机配置

    # 状态（关节角度）：从哪个字段读？
    'state': ['observation.state'],  ← 列表，多个字段会自动拼接

    # 动作（期望关节位）：从哪个字段读？
    'action': ['action'],

    # 指令（任务描述）：从哪个字段读？
    'instruction': 'task_index',  ← 从 tasks.jsonl 读取任务描述
}
💡 关键：数据文件（parquet）中是什么字段名，就写什么。 统一映射到 video/state/action/instruction 四个标准 key。
2️⃣ indices — 状态/动作的维度怎么切分？ 
# 告诉 TAO：你的机器人的关节维度是怎么排列的
indices = {
    'state': {
        # 子组件切分：左臂占 [0,7)，夹爪占 [7,8)
        'sub_components': {
            'left_arm': {'start': 0, 'end': 7},   ← Franka 左臂 7 个关节电机
            'left_eef': {'start': 7, 'end': 8},   ← 夹爪 1 个自由度
        },  ← 总维度 = 8，会被填充到 max_state_dim=128
        'delta_indices': [0],  ← 取当前帧的 state（不是时序的）
    },

    'action': {
        'sub_components': {
            'left_arm': {'start': 0, 'end': 7},
            'left_eef': {'start': 7, 'end': 8},
        },
        'delta_indices': [0..49],  ← 取未来 50 帧作为 action chunk
        'relative_mask': [7, -1],  ← 第 7 维（夹爪）用相对动作，其余用绝对
    },

    'video': { 'delta_indices': [0] },        ← 取当前帧的图像
    'instruction': { 'delta_indices': [0] },  ← 取当前帧的指令
}
💡 sub_components 决定了你的机器人的实际维度； delta_indices 控制取哪些时域帧（[0]=单帧，[0..49]=未来50帧时序块）。 不同机器人的维度差异会在数据加载时自动 padding 到统一空间。

⚠️ 已知陷阱与注意事项
数据相关
  • 训练前必须先生成归一化统计文件（stats.json），否则数据加载会报 assert 错误
  • 数据集必须是 LeRobot 格式：meta/info.json, data/*/*.parquet, videos/*/
  • formalize_language 仅做 lower() + 去标点，不支持同义词替换或语义增强
  • 换语言的一个字可能导致输出异常——这是训练数据覆盖不足的问题，非模型设计缺陷
训练与分布式相关
  • Backbone 默认完全冻结（freeze_module_list=["model"]），只有 Action Head 更新参数
  • HuggingFace Trainer 自动调用 model.train()，会覆盖冻结模块的 eval() 状态。Action Head 通过 set_frozen_modules_to_eval_mode() 修复
  • 恢复训练通过 reseeding 实现（不是 skip data）：new_seed = seed + global_step
  • DiT 来自 diffusers 库的 ModelMixin，不是 HuggingFace 标准模型
  • 视觉编码器的梯度保持通过 dummy term trick 实现（0 × param.sum() 加到 backbone_features 上）
  • SLURM：MASTER_PORT=20000+JOBID尾号 · 使用 torchrun 非 torch.distributed.launch · DeepSpeed ZeRO-2 默认 · multiprocessing_context="fork" · persistent_workers=True
配置与推理相关
  • jsonargparse 将未显式传入的参数用默认值填充，修改默认值时可能不被记录到配置文件中
  • TaoFlowMatchingModelConfig.__post_init__ 中 backbone_config=None 会静默使用默认 BackboneConfigEagleVL25
  • Processor 配置中 image_crop_size 和 image_target_size 通常都是 [224, 224]
  • 检查点保存时 不保存 VL 模型（save_vl_model=False），只保存 Action Head 和配置
  • 推理使用 model.get_action() 而非 model.forward()，默认 num_inference_timesteps=4 步去噪
  • 支持相对动作（relative_chunking）和绝对动作两种模式
